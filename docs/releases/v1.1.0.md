# Production Webapp Toolkit v1.1.0

Status: release candidate documentation

## Purpose

v1.1 turns the toolkit from a collection of repository checks into a composable production-readiness reporting layer. It keeps production truth explicit and separates code quality, Git governance, expected production baseline, deployment identity, evidence recency, and runtime identity.

## New capabilities

* Offline Git governance auditing with local branch, upstream, divergence, and production-candidate visibility.
* Explicit production baseline verification without inferring a production branch.
* Repository status composition across quality, governance, baseline, and deployment dimensions.
* Ecosystem status aggregation across multiple repositories.
* Runtime Evidence Contract v1 for normalized, machine-readable deployment evidence.
* Deployment verification from a full object ID or canonically validated Runtime Evidence file.
* Deterministic evidence freshness policies with explicit evaluation time.
* Explicit runtime identity binding by runtime name and optional environment.

## Status semantics

`PASS`, `WARN`, and `FAIL` deliberately distinguish readiness from technical execution failure.

A quality failure is blocking but is not automatically a technical auditor failure. Governance warnings, unavailable local baseline evidence, deployment mismatch, stale evidence, future-dated evidence, and runtime identity mismatch remain non-technical warnings unless an underlying inspector fails technically.

## Trust boundaries

A structurally valid Runtime Evidence document is not proof that its claims are authentic. `authenticated: true` remains collector-supplied metadata. Freshness measures recency only. Runtime identity binding prevents accidental use of evidence for a different declared runtime but does not authenticate that runtime.

Production baseline selection remains explicit through expected refs and/or commits. Governance candidates, remote defaults, branch names, evidence metadata, and runtime environment labels never select production truth.

## Compatibility

Direct deployed-commit verification remains supported. Runtime Evidence policies are optional; omitting freshness and identity policy preserves the earlier v1.1 behavior.

The reference development and CI toolchain for this release is Node.js 24.21.0 and Bun 1.3.14. The supported Node.js engine line is 24.x.

## Validation

The release gate requires frozen dependency installation, public-repository safety, typecheck, automated tests, lint, build, the complete v1.1 capability surface, pinned toolchain configuration, documentation, and release notes.

Use:

```sh
bun run release:verify
bun run audit:release . --expected-version 1.1.0
```

The exact-version command is expected to fail until the release branch changes the package version to 1.1.0.
