# Production Webapp Toolkit v2.3.0

Status: v2.3.0 minor release

## Status semantics

v2.3.0 keeps the toolkit's deterministic evidence and policy semantics unchanged. It adds an opt-in source-maintenance capability for historical ESLint debt; it does not change deployment truth, repository-manifest interpretation, policy-pack inheritance, or release/deployment authorization.

Known historical lint debt is never reclassified as clean. A baseline records the existing finding multiset and the blocking check permits that debt only to stay equal or decrease. Any finding count above the reviewed baseline is new debt and fails the check.

## Lint Debt Remediation v1

The release adds five explicit commands:

- `lint:debt:scan` inventories tracked JavaScript/TypeScript lint debt.
- `lint:debt:baseline` records the reviewed historical multiset.
- `lint:debt:check` fails on debt above that baseline.
- `lint:debt:plan` previews a bounded automatic cleanup batch.
- `lint:debt:apply` applies one reviewed class of automatic changes.

Baselines are bound to the exact installed ESLint version and SHA-256 of the normalized repository lint-debt policy. Changing the ESLint version or exclusions invalidates the baseline and requires explicit regeneration.

## Trust boundaries

Automatic cleanup is restricted to ESLint fixes whose rule type is `layout`. Problem, suggestion, and directive fixes stay outside automatic mutation.

Apply additionally requires:

- the exact Git repository root;
- a clean worktree;
- tracked regular source files only;
- no followed source symlinks;
- generated and repository-policy exclusions;
- bounded file count and byte count;
- exact output SHA-256 verification;
- no changed paths outside the planned batch;
- a clean `git diff --check`;
- zero newly introduced lint-debt fingerprints;
- a lower total issue count after the batch.

Any failed postcondition restores the original bytes of every file in the selected batch.

A successful apply leaves ordinary uncommitted changes for human review. It never commits, pushes, merges, publishes, deploys, runs migrations, or invokes production/provider operations.

## Policy and generated sources

The public default excludes common generated/build paths and generated filename conventions. Adopting repositories can add exact file or prefix exclusions through Lint Debt Policy v1.

Policy exclusions are part of the baseline identity. They cannot be widened silently without invalidating the baseline.

The public toolkit contains no application-specific protected paths or business rules.

## Verification

Release verification for the feature included:

- 1,760/1,760 toolkit tests passing;
- 11/11 dedicated lint-debt regression tests;
- TypeScript/checkJs passing;
- full ESLint passing;
- public repository safety passing with all new files tracked;
- build reproducibility passing;
- production build passing;
- release-readiness passing.

The regression set covers historical multiset comparison, policy/ESLint binding, generated-path exclusion, exact repository-root enforcement, real CLI baseline/check behavior, layout-only apply, semantic-fix exclusion, dirty-worktree refusal, tracked symlink refusal, and full rollback after a synthetic bad layout fixer fails post-write diff validation.

A read-only proof against the canonical Segara Rasa repository showed 105 pre-existing findings. Ninety-six were layout-fixable but occurred in generated Supabase code or a canonical pricing file and were therefore protected by repository policy. The governed baseline contained the remaining eight warnings; an intentionally introduced scratch lint violation was detected as `newDebt=1` and failed closed.

## Upgrade notes

v2.3.0 is backwards compatible for v2.2.x adopters.

No existing repository manifest, policy-pack, CI Evidence, Runtime Evidence, Release Evidence, or deployment-gate schema changes are required.

Repositories do not receive automatic lint mutations merely by upgrading. Lint Debt Remediation is opt-in and requires explicit scan/baseline/plan/apply commands plus any repository-specific policy needed to protect generated or canonical source paths.

Reference verification:

```sh
bun install --frozen-lockfile
bun run release:verify
bun run audit:release . --expected-version 2.3.0
```
