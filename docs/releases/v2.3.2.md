# Production Webapp Toolkit v2.3.2

Status: v2.3.2 patch release

## Status semantics

v2.3.2 keeps the v2.3.1 lint-debt campaign, bounded layout-only remediation, changed-files lint, evidence, policy, deployment and agent semantics intact.

This patch fixes Lint Debt Remediation finding identity for ESLint rules that do not expose a stable `messageId`. Some such rules include source locations such as `at line 213` inside their message text. A layout-only fix can move the same warning without changing its meaning, which previously changed the raw-message hash and could make the post-apply guardrail report false new debt.

The no-new-debt guardrail is not weakened. Instead, finding identity is explicitly versioned.

## Lint fingerprint v2

Lint fingerprint v2 keeps file path, rule id, severity and stable ESLint `messageId` semantics unchanged.

When `messageId` is unavailable, only volatile `at line N` fragments are normalized to `at line <line>` before hashing. Other numeric content remains unchanged, so messages such as `Expected 2 arguments but received 3` retain their exact semantic identity.

Scans and baselines now carry `fingerprintVersion: 2`. Baseline compatibility fails closed when that version differs or is absent.

## Regression evidence

The defect was reproduced against a real historical-debt cleanup batch in The Happinezz Hills. Under v2.3.1, a layout-only three-file batch correctly removed formatting debt but moved an existing `react-hooks/exhaustive-deps` warning. The embedded line number changed, so the old raw-message fingerprint incorrectly classified it as new debt and rolled the batch back.

With fingerprint v2, the exact same batch succeeds under the existing apply postconditions:

- before: 1,936 findings;
- after: 1,581 findings;
- resolved: 355 findings;
- new debt: 0;
- files changed: exactly the three planner-selected files;
- no guardrail or allowed-path exception was added.

## Trust boundaries

The patch does not broaden automatic mutation authority. `lint:debt:apply` remains restricted to ESLint layout fixes selected by the canonical planner in a clean Git worktree, with tracked regular-file checks, bounded batches, exact output hashes, unexpected-diff detection, `git diff --check`, full post-scan comparison and rollback on failure.

Fingerprint normalization is deliberately narrow. It does not remove arbitrary numbers, paths, rule ids, severities or message text.

## Upgrade notes

### Baseline migration

Existing v2.3.0/v2.3.1 lint-debt baselines do not contain fingerprint version 2 and are intentionally incompatible with v2.3.2. `lint:debt:check` fails closed until the baseline is explicitly reviewed and regenerated.

For an adopting repository:

1. upgrade the toolkit pin to v2.3.2;
2. scan the clean repository with the existing lint-debt policy;
3. compare total issue counts and rule/file distribution with the committed pre-v2 baseline;
4. regenerate the baseline only when those totals and the intended policy scope are accounted for;
5. commit the reviewed fingerprint-v2 baseline;
6. rerun `lint:debt:check` before any cleanup batch.

Baseline regeneration is a fingerprint-schema migration, not permission to accept newly introduced debt.
