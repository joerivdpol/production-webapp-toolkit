# Production Webapp Toolkit v2.0.1

Status: v2.0.1 patch release

## Status semantics

This patch does not change Toolkit v2 status semantics. Required checks, advisory checks, evidence states, deployment gate outcomes, and monotone severity behavior remain unchanged.

## Trust boundaries

High confidence credential patterns and ordinary hardcoded secret assignments remain blocking. The public safety scanner still reports only rule identifiers and paths and never prints matched secret values.

## Changes

Public repository safety now distinguishes narrowly structured nonsecret metadata from hardcoded credentials. Explicit environment indirection such as `env(NAME)` and `${NAME}`, endpoint metadata, credential file or path metadata, and environment key names no longer produce generic hardcoded secret assignment findings when their values match the expected metadata shape.

The change was derived from v2.0.0 integration evidence across real repositories. Provider credential signatures, dotenv file detection, credentialed URL detection, private key detection, registry credential detection, CI secret output detection, and ordinary sensitive literal assignment detection are unchanged.

## Upgrade notes

v2.0.1 is contract compatible with v2.0.0. Projects pinned to v2.0.0 can update their toolkit checkout ref to `v2.0.1` without changing Repository Manifest v1 or policy files.

Reference verification:

```sh
bun install --frozen-lockfile
bun run release:verify
bun run audit:release . --expected-version 2.0.1
```
