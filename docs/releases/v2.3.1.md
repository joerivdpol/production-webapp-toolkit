# Production Webapp Toolkit v2.3.1

Status: v2.3.1 patch release

## Status semantics

v2.3.1 keeps all v2.3.0 lint-debt baseline, ratchet, cleanup, evidence, policy, deployment and agent semantics unchanged.

The patch adds a read-only multi-repository view over the existing Lint Debt Remediation v1 engine. It does not create, update, weaken or approve lint baselines, and it does not grant source-mutation authority.

## Lint Debt Campaign v1

The new `lint:debt:campaign` command accepts one or more explicit repository paths and composes the existing canonical debt scan and layout-only remediation planner.

For each repository it reports:

- current lint issue, error, warning and fixable counts;
- number of linted files;
- default lint-debt baseline state as `PASS`, `FAIL`, `MISSING`, or `INCOMPATIBLE`;
- safe layout-only candidate-file count;
- the next bounded batch file count, byte count and planned resolved-problem count;
- the concrete repository-relative files in that next batch;
- per-file resolved-problem and output-byte counts;
- deterministic cleanup priority.

Priority is ordered by safe next-batch impact, then total lint issue count, then repository path.

One repository failing to scan remains explicit without hiding valid results from other repositories. Duplicate repository paths are collapsed.

## Trust boundaries

Lint Debt Campaign v1 is read only.

Its machine-readable report always sets `mutationAuthorized: false`. It never:

- calls `lint:debt:apply`;
- creates or regenerates a baseline;
- changes repository source;
- changes repository policy;
- installs dependencies;
- commits, pushes, merges, tags, publishes or deploys;
- runs migrations or provider operations.

The existing per-repository `lint:debt:apply` command remains the only lint-debt source-maintenance path. Its clean-worktree, tracked-file, layout-only, bounded-batch, exact-hash, unexpected-diff and rollback protections are unchanged.

The campaign also does not interpret a `MISSING` baseline as approval to create one. Baseline adoption remains an explicit repository decision after generated and protected paths are reviewed.

## Upgrade notes

v2.3.1 is backwards compatible with v2.3.0 and v2.2.x adopters.

No repository manifest, policy-pack, lint-debt baseline, CI Evidence, Runtime Evidence, Release Evidence, deployment-gate, agent-task or other versioned evidence schema changes are required.

Existing lint-debt baselines remain compatible because this patch does not change Lint Debt Policy v1, finding identity, ESLint binding or baseline comparison semantics.

Repositories may adopt the campaign independently of `lint:debt:apply`:

```sh
bun run lint:debt:campaign -- /path/to/repo-a /path/to/repo-b
```

Reference verification:

```sh
bun install --frozen-lockfile
bun run release:verify
bun run audit:release . --expected-version 2.3.1
```
