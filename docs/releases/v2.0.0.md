# Production Webapp Toolkit v2.0.0

Status: v2.0.0 release

Production Webapp Toolkit v2.0 completes the roadmap from repository quality tooling to a generic production-readiness control plane. The public toolkit evaluates explicit engineering contracts and evidence without embedding application-specific business truth, credentials, customer data, or private organization policy.

## Status semantics

The toolkit keeps observed evidence, policy impact, technical inspection failures, and execution authority separate. Existing audits continue to use explicit `PASS`, `WARN`, `FAIL`, `UNVERIFIED`, `MATCH`, or `MISMATCH` semantics where appropriate.

The final Deployment Gate v1 returns only `ALLOW`, `UNVERIFIED`, or `BLOCK`. `ALLOW` means validated supplied evidence satisfies explicit deployment-gate policy. It does not execute, schedule, authorize with a provider, or independently guarantee a deployment.

## Trust boundaries

Evidence authentication metadata is reported as trust metadata; it does not convert stale, inconsistent, failing, or incomplete evidence into a pass. Versioned validators fail closed on unsupported fields and malformed identities rather than repairing or inferring missing production truth.

Inspection and planning capabilities are read-only unless a separately designed safe-autofix boundary explicitly permits a deterministic low-risk repository edit. The deployment gate has no network, provider, shell-execution, environment-read, artifact-upload, or deployment mutation surface.

Private organization policy, canonical application rules, secrets, payment truth, booking truth, and infrastructure credentials remain outside this public repository.

## Capability groups

v1.2 adds production-readiness evidence and policy for CI, GitHub protection, environment contracts, migration/schema/database security, API and cross-repository contracts, dependencies, vulnerabilities, SBOMs, licenses, reproducibility, provenance, release risk, tests, coverage, orphan detection, hygiene, documentation, and ownership.

v1.3 adds runtime evidence collection and health, synthetic/browser assurance, performance, accessibility, SEO, localization, route/auth/webhook/payment/booking/job safety, backup readiness, disaster recovery, and rollback readiness.

v1.4 adds Repository Manifest v1, public policy packs, private organization-policy inheritance, machine-readable ecosystem dashboards, historical comparison, declarative scheduled reporting plans, and monotone severity policy.

v2.0 adds richer remediation metadata, hardened safe autofix, AI-agent safety profiles, diff-aware architecture policy, proposal-only controlled agent workflows, Release Evidence Bundle v1, generic compliance-evidence export, and Deployment Gate v1.

## Upgrade notes

The package version is now 2.0.0. Existing v1.1 entrypoints and versioned contracts remain available unless a newer contract explicitly supersedes them. Projects can adopt the v2 control-plane layers incrementally rather than enabling every policy at once.

Repository manifests and public policy packs remain generic. Organization-specific requirements should be supplied through private policy files instead of modifying the public engine with business rules.

Persisted Release Evidence Bundle and Rollback Readiness Report inputs are structurally validated before deployment-gate use, including canonical coherence/readiness check coverage and exact release-to-rollback identity binding.

The package remains private metadata-wise and is released through Git/GitHub tags rather than an npm publication workflow.

## Verification

Reference release verification:

```sh
bun install --frozen-lockfile
bun run release:verify
bun run audit:release . --expected-version 2.0.0
```

The release gate requires the frozen lockfile, pinned Node/Bun toolchain, blocking CI quality commands, public-repository safety, historical v1.1 baseline capabilities, and the complete public v2.0 script/capability surface documented by the current roadmap.
