# Production Webapp Toolkit v2.3.3

Status: v2.3.3 patch release

## Status semantics

v2.3.3 keeps the v2.3.2 lint fingerprint, baseline, campaign, changed-files lint, evidence, policy, deployment and agent semantics intact.

This patch adds an explicit changed-files-safe mode for bounded historical lint cleanup. It addresses repositories where changed-files lint is blocking while full-repository lint still has legacy semantic debt.

## Changed-files-safe lint cleanup

Use `--changed-files-safe` with lint-debt `plan` or `apply`:

```sh
node scripts/lint-debt.js plan /path/to/repository --changed-files-safe
node scripts/lint-debt.js apply /path/to/repository --changed-files-safe
```
The normal layout-only candidate inventory remains visible. Automatic selection skips a candidate when that file would still contain one or more ESLint errors after the layout preview.

The JSON plan exposes:

- `remainingErrors` for every layout candidate;
- `blockedCandidateFiles` in the summary;
- `changedFilesSafe: true` when the mode is active.

Warnings do not block selection because normal ESLint execution exits successfully on warnings unless a repository separately configures a warning threshold.

## Why this is separate from lint-debt truth

A historical-debt baseline answers whether debt grew. Changed-files lint answers whether a touched file satisfies the repository's current blocking lint rules.

A layout-only cleanup can reduce historical debt while touching a legacy file that still has unrelated semantic errors. That is safe from the debt-ratchet perspective but can correctly fail a blocking changed-files gate.
v2.3.3 does not weaken either control. It prevents automatic selection of such files when the caller explicitly requests changed-files-safe cleanup.

No semantic, problem, or suggestion rule is automatically fixed or suppressed.

## Real repository evidence

The behavior was validated against The Happinezz Hills after the first historical cleanup batch.

The ordinary planner selected two Moka files with large layout debt, but they still contained 30 and 7 blocking `@typescript-eslint/no-explicit-any` errors. GitHub changed-files lint correctly rejected that batch.

Changed-files-safe planning retained those files in the candidate inventory but blocked them from automatic selection. It selected three alternate files with `remainingErrors=0`, reducing the same baseline by 125 findings without introducing new debt.

## Trust boundaries

The flag is opt-in. Existing `plan` and `apply` behavior is unchanged when it is absent.
Automatic mutation remains restricted to ESLint layout fixes under the existing clean-worktree, tracked-file, byte/file-limit, output-hash, unexpected-diff, post-scan and rollback protections.

The mode does not interpret application business rules, weaken lint configuration, modify baselines, suppress diagnostics, or authorize semantic autofixes.

## Upgrade notes

v2.3.3 is baseline-compatible with v2.3.2. Both use lint fingerprint version 2.

Repositories already migrated to a v2.3.2 fingerprint-v2 baseline can update the toolkit pin without regenerating that baseline.

Use changed-files-safe mode for cleanup batches when the repository keeps changed-files lint blocking and legacy files may still contain semantic lint errors.
