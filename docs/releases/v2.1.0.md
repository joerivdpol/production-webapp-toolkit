# Production Webapp Toolkit v2.1.0

Status: v2.1.0 minor release

## Status semantics

Toolkit v2 status semantics remain monotone. Required checks cannot be weakened by lower-priority policy, missing or unverified evidence never becomes PASS, and deployment or agent outputs never create production authority by themselves.

## Trust boundaries

The agent control plane remains evidence-bound and policy-driven. Model output cannot establish repository truth, approve a merge, authorize a deployment, or bypass leases, role policy, repository scope, or deterministic checks.

Vulnerability enrichment keeps OSV as the exact package/version applicability source. GitHub Advisory metadata may enrich UNKNOWN GHSA severity only when advisory id and package family agree.
## Agent control plane

v2.1.0 adds the first complete local agent governance layer:

* Agent Task v1 and persistent task registry.
* Exclusive worker leases for controlled write authority.
* Versioned agent role policy and bounded routing.
* Loopback-only local model adapters and worker discovery.
* Evidence-bound diagnosis and leased reproduction agents.
* Independent review with deterministic evidence requirements.
* A fixed synthetic evaluation corpus for agent behavior.
* Proposal-first repair and protected documentation agents.
* Cross-repository contract impact analysis.
* Dependency maintenance analysis under bounded authority.
## Vulnerability evidence

A new read-only GitHub Advisory enrichment adapter can refine canonical OSV evidence when OSV establishes that an exact installed package version is affected but reports severity as UNKNOWN.

The adapter performs authenticated GitHub Advisory GET requests, deduplicates advisory lookups, verifies the GHSA id and package family, normalizes severity, and merges bounded alias, modified-time, and patched-version metadata. Raw provider payloads and advisory prose are never copied into canonical evidence.

Mixed OSV plus GitHub evidence remains marked unauthenticated because the applicability source is public OSV evidence. Provider disagreement fails closed instead of silently changing applicability truth.
## Upgrade notes

v2.1.0 is additive for existing Toolkit v2 repository manifests and policy packs. Projects pinned to v2.0.1 can move their toolkit checkout ref to `v2.1.0` without adopting the new agent features immediately.

The vulnerability enrichment is opt-in. Existing OSV-only evidence remains valid. Projects that enable enrichment may move from WARN to FAIL when previously UNKNOWN advisories receive HIGH or CRITICAL severity; that is expected evidence refinement rather than a status-semantics change.

Reference verification:

```sh
bun install --frozen-lockfile
bun run release:verify
bun run audit:release . --expected-version 2.1.0
```
